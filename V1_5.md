## 1. Main menu, saves and run history

- [x] Build a proper main menu: **New Game, Continue, Saves, Previous Runs, Memories, Settings, Credits**.
- [x] Display Small Hours, BrokenHours Studio branding and the version clearly.
- [x] Saves: expose the existing autosave, slots, load and import/export workflows cleanly. Distinguish loading a playable save from viewing a completed run.
- [x] Previous Runs: a local archive of completed runs with story seed, Sam's name, outcome and relevant run details. Do not overwrite history when starting a new game.
- [x] Let players replay an archived ending's scene, montage and text without replaying the game or changing an active save.
- [x] Memories: let players browse earned memories for the current run and archived runs, clearly separated by story. Offer access during a run too.
- [x] Keep unseen events and undiscovered endings out of the archive/menu to avoid spoilers.
- [x] Handle empty saves/history/memories honestly; do not manufacture previous runs.
- [x] Explain that history is stored locally in the browser. Include archive/memory backup support in export/import and warn before destructive replacement/deletion.

## 2. Music and small SFX

- [x] Download, verify and include the selected music as game assets in the repository; no third-party streaming dependency at runtime.
- [x] Integrate music throughout appropriate locations, moods, story scenes, ending scenes and memory sequences.
- [x] Add small, restrained SFX where useful, not a sound for every action. Keep intentional quiet, especially during reading/texting.
- [x] Fade between tracks and scenes; avoid abrupt changes, loud stings and constantly restarting the same track on UI redraws.
- [ ] Repeat tracks smoothly; these are full compositions, not verified seamless loops. Test repeat boundaries rather than assuming they are loop-ready.
- [x] Separate music and SFX controls, mute, volume and saved preferences. Make controls accessible from the title/menu and in-game settings on desktop and mobile.
- [x] Respect browser autoplay policies: start/resume only after user interaction, including after loading a save.
- [x] Pause audio appropriately when a scene is paused or the page is backgrounded; resume without overlapping players.
- [x] A failed/missing audio asset must not block gameplay. Show a useful retry option and allow silent play.
- [x] Keep asset sizes/loading practical. Avoid preloading the entire soundtrack before the player can begin.
- [x] Verify both the source page and built/downloadable release resolve assets correctly, including GitHub Pages subpaths and offline use.
- [x] Include track title, author, source, licence link and any modification notes in game credits and repository documentation.

- [x] Fix popup sizing, placement, overflow, layering, long choices and dismissal/back behaviour.

## 4. Figures, faces, icons and clothing

- [x] Create a consistent visual style for scene figures, portraits, faces and interface icons.
- [x] Generate Sam's appearance deterministically per story seed, respecting the player's character choices.
- [x] Keep that appearance stable within a story and across save/load. Different story seeds can produce different Sams.
- [x] Reflect equipped clothing visually wherever relevant; changing an outfit must not reroll Sam's face.
- [x] Match portraits, scene figures and memories so they show recognizably the same person.
- [x] Give NPCs appropriate visual variety while preserving their established identity/details.
- [x] Store generated appearances and historical outfits needed by memories; do not render every past scene in the current outfit.
- [x] Test figure/portrait readability on small screens and with several companions visible.

## 5. Travelling companions

- [x] Fix friend tracking outside Harlow, including other towns, villages, journeys and shared shelter.
- [x] Show present companions in scenes rather than leaving them invisible.
- [x] Keep location, presence, travelling/staying state and interactions consistent across maps, text, scenes and save/load.
- [x] Fix the reported unresponsive-friend interaction problem without violating the standing rule: friends physically travelling with Sam do **not** text/call Sam from beside them.
- [x] Provide usable in-person interaction with present friends; remote friends should respond through messaging when phone/number/connectivity conditions permit.
- [x] Add occasional contextual remarks, shared reactions and in-person conversations, not repetitive chatter.
- [x] Include quiet visual moments: sitting nearby, shared looks, resting or falling asleep together where appropriate.
- [x] Preserve no group splits or jealousy and innocent same-age relationships.

## 6. Writing and ending detail

- [x] Expand scene text where detail strengthens atmosphere and character; avoid padding every routine action.
- [x] Replace em dashes in player-facing writing with fitting punctuation or rewritten sentences. Do not blindly replace source-code operators or unrelated identifiers.
- [ ] Remove repetitive replies and contradictions; NPCs must not re-ask facts they already know.
- [x] Expand endings with distinct scenes and aftermath reflecting the actual run: companions, relationships, shelter, place and consequential choices.
- [x] Preserve existing ending identities and text as the foundation, including the many never-found endings.
- [x] Never claim an event/effect occurred unless it actually did; do not invent playthrough history for added detail.

## 7. Ending sequences, memories and additional scenes

- [x] Add a short text-only outcome title card, e.g. **You got caught.**, followed by an appropriate scene, then the existing/expanded ending text.
- [x] A caught/final outcome sequence must only begin once the outcome is settled; do not play it while Sam can still talk their way out or escape.
- [x] Add a memory montage in **both text and visual scenes**, reviewing meaningful memories from that playthrough rather than just a written recap.
- [x] Cover the recorded memories across the run: leaving home, conversations, friends joining, shelter, kindnesses, difficult moments and turning points. Group/paginate longer histories so the sequence remains navigable.
- [x] Use recorded people, appearances, outfits, places and event details; no invented or unexperienced memories.
- [x] Typical flow: **outcome title → outcome scene → memory montage → detailed ending text**. Adapt the order where an ending calls for it.
- [x] Add scenes for meaningful departures/arrivals, leaving Harlow, friends joining, finding shelter, reunions and major turning points.
- [x] Keep routine purchases/actions/travel quick; do not force a cutscene onto everything.
- [x] Include appropriate music and smooth transitions for scenes and memories.
- [x] Provide Continue, Skip, Pause/resume and reduced-motion controls. Let players read at their own pace rather than forcing timed progression.
- [x] Support readable text speed, including instant text, and font-size settings.
- [x] Replays/viewing memories must be read-only: no replayed effects, time advances, duplicate rewards or active-save changes.

## Implementation boundaries and suggested order

All the above feature suggestions are now included at the user's request. Sequence the work rather than adding unrelated new mechanics:

1. Reproduce companion/UI bugs; define save-compatible appearance, run-history and memory records.
2. Build the visual identity, menu/archive/settings and responsive UI foundations.
3. Integrate local audio with verified licences, settings and failure handling.
4. Implement companion presence, character visuals and contextual interactions.
5. Expand writing/endings and implement scenes, memory montage, browsing and replay.
6. Optimize, regression-test, package and prepare the release.

This roadmap does not override standing gameplay constraints in `FULLMEMORY.md`. Do not add more ending definitions/new simulation systems merely to justify the version number. Implementation authorized; preserve the boundaries during remaining verification.
